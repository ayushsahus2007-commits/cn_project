## Executive summary

This validation checks the implemented finite-model diagnosis engine and runs a reproducible synthetic stress experiment. The main application and this experiment simulate observations; they do not probe real network devices. The synthetic scale study tests algorithm mechanics on directed chains with 10 seeds per size and topology condition, with identical ground-truth faults shared by all four methods for each scenario. It does not establish real-network accuracy.

## Existing architecture

The Node.js service exposes a static browser app and REST endpoints. `uafloc.js` initializes priors, computes entropy and expected information gain, ranks unused probes by information gain divided by positive cost, applies Bayes' rule, and stops at 0.85 confidence, budget exhaustion, or lack of informative probes. `diagnosis.js` persists evidence and belief history in local JSON; `experiments.js` compares adaptive, fixed-order, random-order, and target-ping-first methods over six built-in scenarios. The separate dashboard scheduler also uses simulated telemetry.

## Mathematical and functional checks

The built-in Node test suite includes hand-computable entropy, information gain, and posterior cases; normalization across extreme finite magnitudes; rejection of negative/nonfinite probabilities; zero-likelihood and contradictory evidence; deterministic tie-breaking; probe exhaustion; stopping on ambiguity; custom disconnected and partial topologies; ground-truth withholding; repeated seeded runs; and process-restart session restoration. The validated run passed all 15 tests.

Probe utility is `expected information gain / cost`; tied utilities use probe ID. Bayesian updates normalize each hypothesis' categorical likelihood vector before weighting the prior. An observation with zero total evidence is flagged inconsistent and does not create a posterior.

## Adaptive probe validation

The engine does use entropy reduction: it computes expected posterior entropy from each candidate's likelihoods. The selected probe is the informative available probe with highest information gain per positive cost. Non-informative probes are excluded from UAFLoc selection, and already-used probes are removed. The scale experiment below measures whether this selection recovers the sampled fault more efficiently than the three baselines under the stated synthetic model.

## Termination and persistence

Sessions have a maximum of 20 probes and stop when the top posterior reaches 0.85, the budget is exhausted, or no informative probe remains. A safety loop limit is also present. Tests verify incomplete outcomes, used-probe exclusion, saving an intermediate step, loading the same state in a fresh Node process, continuing the session, and rejecting incomplete/corrupt session records with a conflict response rather than continuing from bad beliefs.

## Partial topology

Custom scenarios preserve explicitly known and unknown directed links, accept isolated nodes and disconnected components, and reject dangling/duplicate/conflicting links. They do not infer missing links. The scale experiment's partial condition withholds direct probes on each fifth link while keeping the same node count and fault distribution. This is a deliberately simple observation-availability stress case, not a packet-level topology simulator.

## Baseline fairness

All four methods receive the same generated scenario, prior, hidden fault, observation likelihoods, stopping threshold, and 20-probe cap. Only probe choice differs: UAFLoc maximizes information gain per cost; fixed uses alphabetical probe order; random samples from all unused positive-cost probes with a deterministic LCG seed; conventional uses the end-to-end target ping first, then alphabetical order. Hidden truth is used only by the simulator to produce an observation and by offline scoring. The regular diagnostic session and scenario APIs do not return truth; experiment result records intentionally include truth for evaluation.

## Ablation and interpretation

The fixed-order baseline provides a limited probe-adaptation comparison while retaining Bayesian updates. The current architecture has no isolated no-Bayes or complete-topology ablation that preserves equivalent observation semantics, so this report does not claim causal effects for Bayesian updating or partial-topology support. Those require additional controlled variants and should be designed before attributing component-level benefits.

## Identified fixes and limitations

Validation exposed two implementation issues and addressed them: probability normalization previously silently discarded invalid weights and could overflow while summing very large finite values; it now rejects invalid weights and scales before summation. The random baseline previously sampled only probes already ranked informative by UAFLoc; it now samples from the same full set of unused positive-cost probes as the non-adaptive baselines. Session restoration now checks stored belief support, normalization, probe history, and scenario consistency before resuming.

The model still uses hand-authored finite hypotheses and deterministic likelihood tables. Experiment scenarios are synthetic, costs are abstract, topology is simple, and outcomes are not learned from traces. Results are not evidence of production diagnostic performance. The benchmark and experiment timings do not represent network response time. The JSON store is for a single-user demonstration.

## Recommended next phase

Collect a labeled, consented set of network fault traces or build a calibrated packet-level simulator; define realistic probe costs and observation noise; pre-register scenario sampling and metrics; then evaluate across independent topologies and fault classes, with confidence intervals and calibration plots. Keep live probing disabled until access controls, timeouts, rate limits, and operator authorization are designed and tested.

## Reproduction

`npm test` runs correctness and persistence tests. `npm run validate` regenerates this report and the JSON measurements from the fixed seed list. `npm run benchmark` separately measures model construction, candidate ranking, and one Bayesian update for 10, 50, and 100-node synthetic models. All scripts perform no network I/O.
